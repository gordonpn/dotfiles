# Implementation Decisions Log

This document records non-obvious engineering and implementation decisions made in Dotfiles, ordered newest first.

## 2026-11-25: Show coding-agent status with Zellij's native tab markers and inbox

- Decision: Keep the stock layout and bind `Alt a` to `ToggleSessionCard` (the inbox) and `Alt Shift a` to `GoToNextAttention` in `dotfiles/zellij.kdl`. Zellij 0.46's tab bar already marks each tab with the status its agent reports.
- Rationale: Claude Code and other agents report working, blocked, done, idle and error with OSC 7501, but only once the terminal answers their probe, which Zellij does from 0.46. The tab bar then shows a marker per tab and a count of tabs that need you, and the inbox lists them across every running session, so the status comes from the agent itself with no hooks, plugins or extra panes. `keybinds clear-defaults=true` drops Zellij's default `Ctrl o` bindings for both actions, so they need keys of their own.
- Rejected alternatives: multiplexer-sidebar in every tab (a terminal pane cannot be made unselectable, so `Alt h`/`Alt l` stopped in it, closing a tab's shell left a tab holding only the sidebar, and a stray `q` quit it), zj-radar (its status comes from its own Claude Code plugin hooks in every agent session, installed with `curl | sh`, which puts third-party code in each agent's hook path), and custom hooks that rename tabs (duplicates the native markers and puts agent state in tab names).
- Known limits: a running session keeps the Zellij server it started on, so a session started on 0.45 or older shows no markers until it is restarted; Zellij 0.45 and older reject the new bindings and with them the whole config.

## 2026-11-24: Enforce agents.delegationAllowed opt-out guard in delegate.sh

- Decision: Check `git -C "$ROOT" config --get agents.delegationAllowed` in `dotfiles/agent-skills/delegate-coding-agents/scripts/delegate.sh` immediately after resolving the repository root and before creating `$LOG_DIR`, worktrees, or MCP profiles or invoking external providers; treat `false`/`0`/`no`/`off` and an explicitly configured empty string (`agents.delegationAllowed=""`, where `git config --get` exits `0` with empty stdout) as fail-closed opt-outs, treat unrecognized values and non-1 `git config` read errors as hard failures, leave unconfigured repositories allowed (`delegation_policy=default`), treat `true`/`1`/`yes`/`on` as `delegation_policy=explicit_allow`, and record `delegation_policy` in `manifest.txt` only on allowed runs so denied invocations abort cleanly with zero orphaned log or worktree artifacts (while keeping `--automatic` as a compatibility flag).
- Rationale: Provides a deterministic mechanical guardrail against accidental external inference inside confidential or employer-restricted repositories under context pressure without reintroducing default-deny opt-in friction on personal repositories, and avoids leaving orphaned `manifest.txt` or worktree directories behind when delegation is blocked.
- Rejected alternatives: Reintroducing a mandatory default-deny `agents.delegationAllowed=true` opt-in across all repositories (blocks routine personal repo delegation), relying solely on prose instructions in `SKILL.md` and `GEMINI.md` (lacks runtime enforcement), creating `$LOG_DIR`/`manifest.txt` (`delegation_policy=explicit_deny`) on denied invocations (leaves orphaned artifacts on blocked runs), or allowing empty/unrecognized config values to fail open (risks silent bypass on misconfiguration or typos).
- Source: [#119 feat(delegate): add mechanical per-repo and remote opt-out guard for external delegation](https://github.com/gordonpn/dotfiles/issues/119).

## 2026-11-22: Convert Tier-1 MCP servers to CLI skills, optimize minimal core profile, and disable postman and sonarqube

- Decision: Add tracked CLI-backed Agent Skills under `dotfiles/agent-skills/` for `semgrep`, `repomix`, and `local-db-cli` (`sqlite3`, `psql`, `redis-cli`), remove `sqlite` and `postgres` from `dotfiles/gemini/mcp_config.template.json` (and perform intentional name-based pruning of `RETIRED_OPENCODE_SERVERS` across both OpenCode and Copilot configs while keeping `redis` in the template as an opt-in non-core server), mark `postman` and `sonarqube` `"disabled": true` by default, and update `DEFAULT_CORE_SERVERS` in `scripts/mcp_sync.py` (plus `tests/verify_mcp.py`, `delegate.sh`, and `opencode-minimal-profile.json`) to the 6 core servers (`ai-memory`, `brave-search`, `cclsp`, `codebase-memory-mcp`, `context7`, `fetch`).
- Rationale: Cuts eager minimal profile turn-0 schema tokens by 54.3% (`~54.1k` to `~24.7k` interactively and `~7.9k` in headless `delegate.sh` runs) by moving `semgrep` (`~22.6k` tokens), `repomix` (`~4.5k` tokens), `git` (`~1.9k` tokens), and `sequentialthinking` (`~700` tokens) onto installed local CLIs and skills while restoring `brave-search` (`~363` tokens) to `core` (enabled unconditionally in minimal profiles for Codex, OpenCode, and interactive Copilot when `BRAVE_API_KEY` is provided at runtime; delegated `delegate.sh --agent copilot` runs remain restricted to built-in CLI tools via `--available-tools`), eliminates plaintext `POSTGRES_URL` credential embedding and single-DB `SQLITE_DB_PATH` coupling in MCP config files through name-based retired-server pruning, and disables unused `postman` (`163.5 KB` schema) and `sonarqube` (`3.9s` JVM cold start).
- Rejected alternatives: Keeping `semgrep`, `repomix`, `git`, and `sequentialthinking` in `DEFAULT_CORE_SERVERS`, retaining `postgres` and `sqlite` MCP servers with inline config arguments, or leaving `postman` and `sonarqube` enabled by default despite zero active usage.

## 2026-11-22: Extract embedded Python and config/skill sync from bin/mcp-sync into scripts/mcp_sync.py

- Decision: Move the embedded Python blocks, JSON/JSONC/TOML hydration and rendering, SSH/Docker/K3s profile generation, and skill/instruction symlink orchestration out of `bin/mcp-sync` into a typed zero-dependency Python 3.11+ stdlib module (`scripts/mcp_sync.py`) verified by `ruff`, `mypy --strict`, and `tests/test_mcp_sync_py.py`, while keeping `bin/mcp-sync` as a thin Bash entrypoint preserving CLI flags, binary installers, and shell test compatibility.
- Rationale: Eliminates embedded-language Python blocks inside Bash, removes macOS Bash 3.2 associative-array string workarounds, avoids quote-injection hazards by hydrating template placeholders after `json.loads`, and maintains sub-100ms cold-start overhead on shell startup hooks without requiring third-party runtime packages.
- Rejected alternatives: Rewriting all small shell wrappers (`agy-statusline`, `title.sh`, `cbcopy`, `update-skills.sh`) into Python (adds interpreter startup latency and subprocess boilerplate for simple pipelines), or introducing `uv` / third-party TOML writers into the shell startup path.
- Source: [PR #127](https://github.com/gordonpn/dotfiles/pull/127) (`refactor/mcp-sync-python`).

## 2026-11-22: Hybrid Codex-first routing using Codex plugin for read-only continuity and delegate.sh for worktree builds

- Decision: Update Antigravity CLI routing in `dotfiles/gemini/antigravity-cli/rules/auto-delegation.md`, `dotfiles/gemini/GEMINI.md`, `dotfiles/agent-skills/delegate-coding-agents/SKILL.md`, `README.md`, and `docs/mcp-setup.md` so substantive requests route Codex-first via the user-installed Antigravity Codex plugin (`$HOME/.gemini/config/plugins/codex/scripts/codex-runner.mjs` in read-only mode with `--resume-last`, gated on runner presence) for questions, debugging, planning, architecture discussions, reviews, and technical research, while retaining `delegate.sh` (`--mode build`) for implementation writes inside isolated Git worktrees, keeping automatic fallback through `--agent opencode` (skipping redundant Codex retry on plugin quota failures) and GitHub Copilot Student without blocking for confirmation, and requiring uncommitted diffs to be passed explicitly during fallback `plan` reviews on dirty checkouts.

- Rejected alternatives: Replacing `delegate.sh` entirely for workspace edits (loses isolated worktrees, dirty-base overlap protection, and multi-provider OpenCode/Copilot fallback), assuming `codex-runner.mjs` is always pre-installed without a presence check, or pausing to ask before every fallback (adds interactive round-trips during automated runs).

## 2026-11-19: Drop delegate.sh opt-in and dirty-tree gates and prefer external delegation over invoke_subagent

- Decision: Remove the blocking `agents.delegationAllowed=true` check (`--automatic` remains accepted as a compatibility no-op) and blocking clean-working-tree check from `delegate.sh`, warn on stderr, record `dirty_base=1` and `dirty_base_overlap=0|1` in `manifest.txt`, print a `Base snapshot note` and any `Overlapping dirty base files` in `DELEGATION_RESULT` when uncommitted or untracked base edits exist, require manual hunk reconciliation rather than whole-file overwrites or resets when integrating overlapping dirty files, and instruct Antigravity (`agy`) in `dotfiles/gemini/GEMINI.md`, `auto-delegation.md`, and `delegate-coding-agents/SKILL.md` to prefer `delegate.sh` over native `invoke_subagent` (with confidentiality enforced by orchestrator policy rather than a per-repo script opt-in gate).
- Rationale: Unblock automatic delegation across personal repositories (including worktrees or checkouts with unrelated uncommitted files like `NEXT.md`) and offload eligible work onto Codex, free OpenCode models, and Copilot Student rather than defaulting to `invoke_subagent` on Antigravity quota, while keeping snapshot semantics transparent and preventing local uncommitted work from being clobbered when worker changes overlap with dirty base files.
- Rejected alternatives: Requiring an opt-in git config per repo (`agents.delegationAllowed=true`) or failing whenever local files are dirty (blocked routine delegation on personal repos), auto-stashing/copying dirty working trees into the worker worktree (risks leaking `.env`/untracked artifacts or breaking cherry-picks), or defaulting Antigravity to `invoke_subagent` (consumes Antigravity quota instead of Codex/OpenCode/Copilot).
- Source: [PR #117](https://github.com/gordonpn/dotfiles/pull/117) (`feat/prefer-delegate-drop-gates`).

## 2026-11-15: Adopt three-tier MCP architecture and lock server dispositions

- Decision: Formalize a three-tier MCP distribution policy in [`docs/mcp-audit.md`](mcp-audit.md): (1) eager clients (`codex`, `opencode`, `copilot`, and `delegate.sh`) receive only a lean `core` (`< 100` tools) keeping `context7`, `fetch`, `cclsp`, `codebase-memory-mcp`, `brave-search`, and interactive `ai-memory`; (2) CLI-covered integrations (`semgrep`, `repomix`, `git`, `sequentialthinking`, `sqlite`, `postgres`, `redis`) move out of eager profiles onto native CLIs and Agent Skills; and (3) retain `filesystem` (preserving `${HOME}` root scoping on `agy`) and `exa` (lazy semantic search fallback on `agy` alongside `brave-search`), while disabling `discord`, `caddy`, and `vault` (`caddy` and `vault` unreachable over Tailscale; `discord` unused) and deleting broken/superseded legacy entries (`server-services-configs`, `chrome-devtools`, `puppeteer`, `memory`).
- Rationale: Cuts eager minimal profile turn-0 schema cost by ~54.3% (`~54.1k` to `~24.7k` tokens interactively and `~7.9k` headless) while preserving web search coverage (`brave-search` in `core` + `exa` lazy on `agy`) and `${HOME}` scoping on `agy` (`filesystem`), without running unreachable or unused daemon/admin servers.
- Rejected alternatives: Removing `brave-search` or `exa` despite complementary keyword/semantic search workflows, removing `filesystem` despite its explicit `${HOME}` root allowlist on `agy`, introducing a custom MCP proxy daemon (rejected in #30/#41), or keeping unmaintained/unreachable `caddy`, `vault`, and legacy entries active.
- Source: [#70 investigation: audit MCP servers and classify as keep MCP, CLI + skill, or lazy-load/code-execution](https://github.com/gordonpn/dotfiles/issues/70), [PR #105](https://github.com/gordonpn/dotfiles/pull/105), follow-ups [#100](https://github.com/gordonpn/dotfiles/issues/100)-[#104](https://github.com/gordonpn/dotfiles/issues/104).

## 2026-11-02: Exclude standard path tools from Carapace completions

- Decision: Add standard file and path tools (`basename`, `chmod`, `chown`, `dirname`, `du`, `file`, `readlink`, `realpath`, `stat`, `wc`) to `CARAPACE_EXCLUDES` in `dotfiles/.zshrc_new` alongside existing exclusions, and pass `-e CARAPACE_EXCLUDES -e CARAPACE_MATCH` to `_zcache_source`.
- Rationale: Prevent Carapace's generic completers from intercepting standard path tool completions and double-escaping paths containing spaces under `fzf-tab`, while ensuring edits to `CARAPACE_EXCLUDES` invalidate the cached Carapace init script.
- Rejected alternatives: Relying on Carapace's built-in completers for standard file utilities or manually clearing the zsh completion cache after every `CARAPACE_EXCLUDES` edit.
- Source: [#13 fix(zsh): exclude standard path tools from carapace completions](https://github.com/gordonpn/dotfiles/pull/13)

## 2026-10-29: Enforce mandatory task-branch pull request delivery

- Decision: Require every repository change (code, tests, configuration, documentation, scripts, and agent rules) to be committed on a dedicated task branch and delivered through a pull request targeting the default branch, never committing directly to or fast-forwarding `main` or `master`.
- Rationale: Maintain reviewable, isolated history across repositories and prevent unreviewed changes from landing directly on shared default branches.
- Rejected alternatives: Committing or fast-forwarding changes directly onto `main` or `master`.
- Source: [#12 docs(rules): enforce mandatory pull request delivery for all changes](https://github.com/gordonpn/dotfiles/pull/12)
